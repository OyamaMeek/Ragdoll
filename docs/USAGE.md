# 使用指南

[返回 README](../README.md) · [开发文档](DEVELOPMENT.md)

## 首次启动

选择本地专用 Git 用量仓库，也可选择空目录创建仓库。Git 需要配置 `user.name` 和 `user.email`。完成设置前不扫描本机日志。

已配置后立即展示主界面和本地用量缓存，侧栏显示读取进度。先恢复仓库中的历史用量，再扫描本机新增记录。仓库失效或读取失败时保留已有缓存，可重试或重选；失败期间停止归档写入。

## 会话用量

应用自动读取 `CODEX_HOME`、`CLAUDE_CONFIG_DIR`、`DSH_HOME` 或各工具默认目录，可在设置中调整。

“会话用量”支持按名称、项目或会话 ID 搜索，按来源和项目筛选。点击会话查看总 Token、输入、输出、缓存读取、缓存写入，以及每条用量的模型和时间。缺少原始用量时显示未知。

保存内容限于会话身份、名称、来源、项目、时间及 Token 明细。名称可能来自工具保存的标题，缺少标题时使用首次有效提问的前 100 个字符作为名称。源日志保持只读。

## 激活 Codex 5h 窗口

侧栏“Codex 账号”显示已安装 Codex Tools 中保存的 ChatGPT 账号，包括邮箱、套餐、本机当前登录、5h/周使用率、剩余额度与重置时间。点击账号查看详情，“刷新额度”重新获取所有账号状态；旧数据读取失败时会明确标记。

每个账号都有独立的“切换”和“激活 5h 窗口”按钮。激活指定账号不改变本机当前登录，操作前通过 Codex Tools 刷新该账号的登录与额度。切换确认成功后自动正常退出并重新打开 ChatGPT（Codex 桌面端），让桌面端读取新登录；退出会中断运行中的任务。独立 CLI 进程请手动重新打开。

切换存在历史同步警告时先显示警告，不自动重新打开。桌面端拒绝退出、15 秒内未退出或重新打开失败时，显示“本机登录已切换”及具体处理提示，保留已取得的账号状态，不强制终止应用。

账号页需要 `/Applications/Codex Tools.app` 及其现有账号库；添加账号、重新登录和账号维护在 Codex Tools 中完成。Ragdoll 不另建凭据库，不把账号凭据写入 SQLite 或 Git 备份。

在“设置 → 数据来源”的 Codex 目录旁点击“激活 5h 窗口”。使用该目录 `auth.json` 中现有的 ChatGPT 登录，仅向官方接口发送固定 `hello`，不创建本地对话，不保存或备份凭据。API Key 账号不支持；凭据缺失或过期时，请通过对应 Codex 重新登录。

操作先查询额度；窗口已激活或额度耗尽时跳过推理。否则发送一次真实请求，完成后重新查询，分别显示“已激活”或“请求完成但尚未确认”。请求会消耗少量额度，不会重置已有窗口；启动时间由服务端决定。超时或失败不会自动重试，可能已消耗额度，请先确认账号状态后再操作。

### 窗口刷新后自动激活

在对应账号下打开“窗口刷新后自动激活”（默认关闭）。开启时先读取当前窗口重置时间并等待，重置后留 30 秒缓冲，再刷新额度、按需发送一次固定 `hello`。每个账号分别保存开关、下次检查时间和最近结果；不会切换当前登录。

保持 Ragdoll 运行即可自动检查；已启用“设置 → Git 用量备份 → 独立后台服务”时，退出界面后继续。电脑休眠或关机期间不发送，恢复运行后再检查；前台一般每 15 秒检查一次，后台也可能因正在扫描或备份而延迟。不会补发多条错过的消息。

已有活动窗口时等待实际重置时间；额度耗尽时等待额度恢复。免费查询失败会在 5 分钟后再查。请求完成但窗口尚未确认时，至少等待 5h 再检查；推理失败或进程中断导致结果未知时暂停，检查结果后关闭再开启。账号页的手动激活结果同样会更新自动等待状态。

关闭开关会取消尚未发出的自动请求；已经发送的请求可能继续完成。状态保存在应用数据目录的 `codex-auto-activation.json`，不含凭据或消息正文，不进入用量备份。状态文件损坏时停止自动请求并保留原文件。

### 额度刷新后向原会话发送一次消息

在“Codex 账号”中切换到要使用的账号，等待桌面端重新打开并刷新额度。在该账号卡片的“下次额度刷新后发送一次”中选择项目、选择会话、输入消息，再点击“设置一次性发送”。项目按最近会话更新时间倒序排列。会话来自桌面端当前数据目录下已扫描的原生 Codex 会话，名称后附会话 ID 前八位以便区分。

计划会等待启用时的下一次 5h 重置时间，留 30 秒缓冲后刷新额度，再将原样消息交给桌面端原会话的持久队列并唤醒该会话。由桌面端按原会话的模型、权限和队列规则继续执行；已有任务和其他排队消息仍由桌面端处理。界面显示“消息已交给桌面端原会话”表示已确认入队，执行结果请在原会话查看。消息会消耗账号额度。

每个账号最多保存一条计划，确认入队后自动关闭。等待时可以点击“取消计划”；修改内容需要先取消再设置。已经交给桌面端的消息请在原会话中检查或取消。账号发生变化、会话失效或发送结果不明时暂停，不自动重复发送；先查看原会话及其队列，再决定是否重新设置。Ragdoll 不会为此自动切换登录或重启桌面端。

保持 Ragdoll 运行，或启用独立后台服务。休眠、关机或后台正在处理其他工作时会延后，恢复后只处理这一条消息；周额度仍然耗尽时等待额度恢复。当前需要支持原生 `thread/queue` 接口的 ChatGPT（Codex 桌面端），旧版不支持时会明确报错。Ragdoll 使用桌面端内置 Codex 进行队列操作，辅助进程不运行模型步骤。

计划保存在应用数据目录的 `codex-scheduled-message.json`，权限为仅当前用户读写，包含你输入的消息、目标和最近状态，不含登录凭据，不进入会话用量备份。状态文件损坏时停止自动发送并保留原文件。

## 首页与预算

热力图按本地自然日汇总 Token。当前年份展示过去一年，历史年份展示完整自然年；悬停查看每日用量，点击日期筛选会话。项目和来源筛选同样适用于统计。

“DeepSeek V4.1 Flash”卡片默认显示峰价人民币估价，点击切换谷价。两档均使用当前筛选的输入、输出及缓存明细计算。[DeepSeek 官方价目](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)

“设置 → 首页 → 显示每周预算”默认关闭，开启后展示滚动 168 小时预算及 80% / 100% 提醒。美元成本使用当前价格表估算，缺少价格或用量显示未知；历史调价、服务层级等因素会影响估算。

## Git 用量备份

“设置 → Git 用量备份”可更换仓库、立即备份、排除项目、设置远端和后台服务。

新增用量保存在 `usage/<来源>/<会话>.json`，摘要校验保存在 `.ragdoll-usage-manifest.json`。自动保存采用 30 秒防抖，最长合并 5 分钟，并创建本地提交。取消备份的项目仍可查看统计；已有备份保留。

仓库根目录 `README.md` 的活动区块显示成本、Token、会话数、近一年热力图、项目统计和最近会话，标题链接指向用量 JSON。手写 README 正文保留；人工改动应先保存或提交，生成区块和用量文件的手工修改会阻止自动覆盖。

旧归档只读取 `metadata.json` 中的用量；旧正文、原始文件、附件与 Git 历史保留，不再新增这些内容。需要完全不含旧正文的远端仓库时，选择新的专用用量仓库。

远端推送沿用系统 Git 和 SSH 配置，上传所选分支的全部历史。沿用旧仓库时，历史仍可能含有正文与附件。单次最长 90 秒，失败保留本地提交并重试。远端分歧需要自行处理；应用不自动拉取、合并或强制推送。多个 push URL 会被拒绝。

## 索引迁移与恢复

索引位于 `~/Library/Application Support/Ragdoll/index.sqlite`。首次打开旧索引时，先通过 SQLite 生成同目录的 `index.sqlite.before-usage` 恢复副本，再在事务中保留每会话用量、删除正文及全文搜索数据，最后回收空闲页面。

恢复副本仍包含原始正文并占用磁盘空间。确认新索引和用量备份完整后，可手动移走或删除。旧工具版本不兼容精简后的索引；需要恢复时先退出应用及后台服务，保留当前用量索引，再将恢复副本复制为 `index.sqlite`，配合旧版本应用使用。

若恢复副本已存在但索引仍是旧格式，迁移会停止，避免覆盖恢复点；先妥善保留并移走该副本，再重试。迁移读取到损坏数据时保留原库并报告错误。

## 独立后台服务

在打包应用的“设置 → Git 用量备份”启用当前用户的后台登录项，退出界面后继续扫描、备份和重试推送，注销时停止。未启用时使用应用内调度。

应用与 helper 需要同一个有效 Apple 签名，外置磁盘和受保护目录还需要系统访问权限。详见[签名与后台服务](DEVELOPMENT.md#签名与后台服务)和[验证记录](VALIDATION.md)。
